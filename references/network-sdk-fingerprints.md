# 网络验证 SDK 指纹库与通用打法

> **为什么这是命中率最高的一块**：外挂 / 辅助 / 脚本类目标绝大多数不是自研验证，
> 而是接的**商业网络验证 SDK**（天御、易游、飘零、飞扬、至简、索玛…）。
> 同一 SDK 的客户端结构是标准化模板：判定点位置、缓存方式、续期机制都同构。
> **认出家族 = 少花 2 小时从零扫代码，直接照模板打。**

## 一、30 秒识别的五个信号（顺序别乱）

| # | 信号 | 怎么取 | 看到什么说明什么 |
|---|---|---|---|
| 1 | **域名 / 接口路径** | `strings -a lib/*.so`、`grep -rn "http" apk_out/smali`（注意字符串可能运行时解密） | `xxx.com/api/client/...`、`client.php`、`verify`、`kami`、`card` → 标准 SDK 布局 |
| 2 | **错误文案** | APK 内搜中文：`卡密不存在` / `已被使用` / `机器码不匹配` / `授权已过期` / `绑定数已满` / `请先登录` | 文案能直接反推是哪个 SDK 的响应模板（各家族用词固定） |
| 3 | **类名 / 包名 / so 名** | `grep -rniE "tyun\|天御\|易游\|飘零\|飞扬\|至简\|soma\|华夏\|酷爱\|卡密宝" apk_out/`；`ls lib/arm64-v8a/` | 命中家族名 = 直接归族；so 名常含 `sdk`/`verify`/短随机串 |
| 4 | **本地缓存落点** | 运行后看 `SharedPreferences` / `files/` / 外部存储的 `.dat` `.lic` `.bin` | 缓存文件 = 第 ② 号判定点（最稳的打点）所在 |
| 5 | **抓包字段** | 首次激活 + 心跳各抓一次 | `card/kami/key` + `mac/machine/mcode` + `sign` + `timestamp/nonce` 四件套 = 标准 SDK 协议 |

命中 1 个只算线索，**命中 3 个以上再下家族结论**；不确定就写"疑似 XX 家族（待实测）"。

## 二、通用架构：五个判定点（所有网络验证家族通用）

```
首次激活 ──► 服务端校验(卡密+机器码) ──► 返回票据/到期时间 ──► 本地缓存
                                                              │
每次启动 ──► 读缓存 ──► 有效期比较 ──► 放行功能 ──► (后台心跳续期)
                                   └─ 到期/失败 ──► 弹验证窗
```

| 打点 | 位置 | 代价 | 稳定性 | 备注 |
|---|---|---|---|---|
| ② 缓存有效期比较 | 读本地缓存后的 `if (expire > now)` | 低 | **最高** | 断网可用，服务端难纠正；首选 |
| ① 响应解析判定 | 收到响应后判 `success/code` 字段的分支 | 低 | 高 | 不伪造响应，只改客户端判定 |
| ⑤ 功能层二次校验 | `isVip()` / `isAuthorized()` 等方法 | 低 | 中 | 必须**全族枚举**（见 SKILL 1.4） |
| ③ 机器码比较 | 本地 machine code 与服务器返回值比较 | 中 | 中 | 绑定型目标才需要 |
| ④ 心跳/续期 | 后台定时请求 + 失败降级 | 中 | — | **只改 ①② 不改 ④ = 用一会儿又被纠正**：把续期失败路径一并改成"保持有效" |
| mock 服务端 | hosts + 本地服务 | 高 | 中 | 响应有签名时不建议（先看 §1 信号 5 的 `sign`） |

**优先顺序**：② > ① > ⑤ > ③ > mock。**任何家族都先看缓存文件**——多数 SDK 的缓存是明文或简单异或。

## 三、家族登记表（识别用名单；细节逐案回填）

> 状态口径：**结构性结论**（写在正文的架构/打点）已验证通用；**每格具体指纹**需首次遇到时采集回填，
> 不许凭印象填。识别到家族名即可标"已归族"，打法统一走 §二。

| 家族 | 常见识别信号（域名/文案/类名） | 状态 |
|---|---|---|

| 易游网络验证（YY） | 字符串含 `yy`+验证语义、`易游`；接口常带 `client/` 路径 | 待实测回填 |
| 飘零网络验证 | 字符串含 `飘零` / `pl` 前缀类名 | 待实测回填 |
| 飞扬网络验证 | 字符串含 `飞扬` / `feiyang` | 待实测回填 |
| 至简网络验证 | 含 `至简` / `zhijian` | 待实测回填 |
| 索玛 SOMA | 含 `soma` / `索玛` | 待实测回填 |

**回填义务**：每次做完一个网络验证目标，把「家族名 / 域名特征 / 缓存文件路径 / 判定点文件:行 / 是否带签名」补进本表，
这是 skill 提高命中率的主要途径之一。

## 四、落地检测命令

```bash
# 1) 家族名扫描（解包目录）
grep -rniE "tyun|天御|易游|yy_?verify|飘零|飞扬|至简|zhijian|soma|索玛|华夏|酷爱|卡密宝|秒卡" apk_out/ | head -20

# 2) so 里的接口与文案（字符串可能加密，命中即价值）
strings -a apk_out/lib/arm64-v8a/*.so | grep -iE "https?://|/api/|verify|kami|card|机器码|卡密|到期"

# 3) 缓存落点（root 真机 / 模拟器安装一次后）
adb shell "find /data/data/<包名>/ -name '*.dat' -o -name '*.lic' -o -name '*.bin'" 
adb shell "cat /data/data/<包名>/shared_prefs/*.xml" | head -40

# 4) 抓包比对首次激活 vs 心跳（三态法）
#   首次：有 card+mac+sign；心跳：通常只有 ticket/token → 判定②④位置
```
